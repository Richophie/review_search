# 실시간 공고 데이터 갱신 및 운영 배포

2026-10-14 · 체험단 모아보기

## 실시간 데이터 설계
- TanStack Start 서버 함수가 공식 GitHub raw URL에서 검증된 public/data/campaigns.json을 불러온다.
- 서버 측 10분 캐시, 동시 요청 공유. 일시 장애 시 마지막 성공 데이터 또는 빌드 시점 정상 데이터를 제공하고 90초 후 재시도한다.
- 사용자가 외부 데이터 URL을 지정할 수 없다. 중복 ID·원본 링크, 미등록 출처, 잘못된 필수 필드가 있으면 갱신 파일 전체를 거부한다.
- 데이터 변경만으로 운영 검색이 최신 스냅샷을 읽도록 하여 빌드 사용량을 줄인다.

## Vercel 배포 정책
- Ignored Build Step 명령: bash scripts/vercel_ignore_build.sh
- 검증된 JSON 스냅샷 및 문서만 변경된 커밋은 빌드 생략한다.
- 수집·검증·앱 소스·자동화 설정은 매번 빌드한다. Git 변경 파일을 확인할 수 없으면 안전하게 빌드한다.

## 2026-10-14 공고 감소 검증
- 15,465건에서 11,610건으로 줄어든 변경을 두 버전의 캠페인 ID별로 교차 검사했다.
- 제거 5,877건 중 5,876건은 신청 기한 만료, 1건은 미상 마감일 48시간 확인 기한 만료였다.
- 새로 확인된 공고는 2,022건이다. 임의로 만료된 공고를 재수록하지 않는다.

## 운영 검증 및 잔여 작업
- scripts/smoke_live_snapshot.py: GitHub 상태 파일과 SSR 표시 건수 비교. 10분 캐시 지연을 감안해 2.5% 오차만 허용.
- 리뷰노트 썸네일 누락 75건은 원본에서 실 이미지 확인 전 임의 이미지로 대체하지 않는다.
- 매체 미분류는 원본 사이트의 공개 배지가 있어야만 분류한다. 임의로 블로그라고 지정하지 않는다.
